Add cross-process locking to the file adapters. Pass `lock: { sleep, staleMs?, timeoutMs?, retryMs? }` to `fileAdapter`, `jsonFileAdapter`, `yamlFileAdapter` or `iniFileAdapter` and every write and removal first takes a lock file (`<key>.json.lock` beside the key's file, or `<file>.lock` beside the document) made with the file system's exclusive create, so several processes can share one directory or document without losing updates, and `ifRevision` is checked against what another process just wrote. With four real processes each adding to a shared counter 25 times, 66 of 100 additions were lost without the lock and none with it. A lock that cannot be had within `timeoutMs` gives `unavailable` naming the lock file and writes nothing; a lock older than `staleMs` is taken to be left by a dead process and is broken, and a lock is only released if it is still the one that write took. You pass `sleep`, so the library still has no timers. It needs a `FileSystemLike` with `writeNewFile` (`nodeFileSystem()` has it) and a file system where exclusive create is atomic, and it is advisory: it protects writers that all use it. Without `lock` nothing changes.
