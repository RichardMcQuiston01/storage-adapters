Add a Firestore adapter as the optional `@richardmcquiston01/storage-adapters/firebase` entry point. `firestoreAdapter({ store, now?, onWatchError? })` keeps each key as one document (`key`, `value`, a counter `revision`, `created_at`, `updated_at`) in a collection, with the key's characters other than letters, digits and `-` escaped in the document id, since Firestore ids cannot hold `/`, `.`, `..` or `__name__`. A transaction reads then writes the document, so `set` with `ifRevision` is atomic across clients (a key with nothing stored is created). No SDK is bundled: `firestoreStoreFromAdmin({ firestore, collection? })` wraps `@google-cloud/firestore` or `firebase-admin`, and `firestoreStoreFromWebSdk({ firestore, sdk, collection? })` wraps `firebase/firestore`; or pass your own `FirestoreStoreLike`. `subscribe` listens to the document with `onSnapshot`, so it reports other clients' changes as well as your own, once each. `list` is a range query on `key`. SDK errors map to `forbidden`, `quota`, `invalid` and `unavailable`, a document that is not a stored entry is `corrupt`, and messages name the key. Security rules stay your job.
