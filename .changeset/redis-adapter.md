Add a Redis adapter as the optional `@richardmcquiston01/storage-adapters/redis` entry point. `redisAdapter({ client, prefix?, ttlSeconds?, subscriber?, onSubscriberError? })` keeps each key as a Redis hash holding a counter revision and the value, and works with Redis, Valkey, KeyDB and Dragonfly. A Lua script checks the revision, writes, sets the expiry and announces the change in one step, so `set` with `ifRevision` is atomic across processes (a key with nothing stored is created). No client is bundled: `redisCommandsFromIoredis(client)` and `redisCommandsFromNodeRedis(client)` wrap `ioredis` and node-redis, or pass anything with `command(args)`. `ttlSeconds` expires keys after each write for cache-style data. `subscribe` reports changes made through the same adapter, and, given a `subscriber` connection (`redisSubscriberFromIoredis`, `redisSubscriberFromNodeRedis`), changes other processes make with the same prefix, over Pub/Sub.
