Add the optional `@richardmcquiston01/storage-adapters/yaml-file` and `@richardmcquiston01/storage-adapters/ini-file` entry points with `yamlFileAdapter({ path, fileSystem, yaml })` and `iniFileAdapter({ path, fileSystem, ini })`: `StorageAdapter`s that keep every key in one hand-editable file, `key: value` in YAML and `key=value` in INI. No parser is bundled; pass in the `yaml` or `ini` package (anything with `parse` and `stringify`). There is no revision in the file: the revision is a fingerprint of the value, so a hand edit is noticed as a new revision and a layout or comment change is not. A value is text (a string, `true`/`false`, or a whole number); anything else is `corrupt` for that key and is kept as it is when other keys are written. A key or value the format would not read back as the same text, such as the INI value `null` or key `a=b`, is refused with `invalid` before anything is written. Like `jsonFileAdapter`: cached reads, queued writes that replace the file atomically, a broken file is never overwritten, outside edits noticed when the file system can watch, `cache` and `watch` options. Comments and layout are not kept when the adapter writes. Safe within one process only. The main entry stays free of I/O.
